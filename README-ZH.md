# ManifestHub — 身份转化引擎

> **通过连接身份、愿景和日常行动，重塑你对人生的理解。**

ManifestHub 是一个身份驱动的显化操作系统，基于《如何在一天内改变你的整个人生》框架构建。它帮助用户挖掘反愿景、锚定一个 6 元素身份地基，并闭合"自己声称是谁"与"行动所揭示的真实"之间的鸿沟。

## 产品哲学

### 根本问题

用户陷入了一个显化陷阱：他们知道自己*想要什么*，但从未认真思考过**为了自然地生活在那个世界里，自己需要成为谁**。传统的目标追踪应用（日历、待办清单、静态肯定语录）强化了"目标导向"而不是"身份转化"，这就是为什么 93% 的新年决心在 1 月中旬就失败了。

ManifestHub 把这个逻辑翻过来：**身份优先，目标其次**。它锚定在原框架的七个核心命题上：

1. **身份决定行为** — 你不是你的目标；你是你的身份，行为是副产物
2. **所有行为都是目标导向的** — 你的目标充当感知滤镜；改变目标，就改变了你看到的世界
3. **身份会自我保护** — 恐惧驱动的回避伪装成"现实主义"；这需要被挖掘出来
4. **意识有阶段** — 你能否到达目的地取决于你当前的心智阶段
5. **智能 = 控制论** — 行动 → 感知 → 比较 → 调整；每周和每年都要闭合这个循环
6. **一日重启协议** — 晨间挖掘 → 日间打断 → 夜间合成，一天内完成
7. **把人生当游戏** — 反愿景 / 愿景 / 一年镜头 / 一月项目 / 每日杠杆 / 约束条件

### 为什么这很重要

**吸引力法则重新定义为操作系统：**

原框架不是神秘学——它是应用控制论 + 行为心理学：

- **反愿景**暴露了你努力背后的*引力*（你在逃离什么比你在追求什么能更快地驱动改变）
- **身份陈述**锁定了信念；信念塑造感知；感知塑造行为
- **每日杠杆**（未来的你会毫无谈判地做的 2–3 个行动）绕过前额皮质，直接运行在自动驾驶模式下
- **周复盘**闭合反馈循环：我的*行动*是否与我的*身份宣言*一致？

**这个产品不是关于运气或神秘的显化。** 它是关于**严谨的身份对齐**，可选的 AI 来镜像矛盾。

## 核心设计原则

### 1. **身份优先，不是目标中心**

每个功能的默认问题都是"我正在成为谁？"而不是"我想要什么？"

- Dashboard 英雄区：你当前的身份陈述（不是静态 i18n 肯定语）
- 肯定语旋转木马：从你的地基自动生成（反愿景 / 愿景 / 月项目 / 年镜头）
- 意图输入框：*"今天，[身份陈述]版本的你会做什么？"*
- 愿景卡片：包含 `identityLink` 字段——这张卡如何服务于你的身份？

### 2. **反愿景先于愿景**

用户直觉上更清晰地知道自己厌恶什么而不是热爱什么。从那里开始。

- "我绝不让我的人生变成……"是地基和重启协议中的第一个提示
- 这种负面能量变成了*方向速度*——比抽象的志向更快
- 反愿景还防止了"刺猬困境"：你既在朝愿景移动，也在远离反愿景

### 3. **层级式，不是平铺**

不是所有愿景都平等。镜头层级映射了游戏设计的结构：

```
年镜头      (1 张)  — 证明旧模式被打破的那一件事
   ↓
月项目     (1–2)   — 本月的 boss 战
   ↓
周任务     (2–4)   — 每周日刷新的小目标
   ↓
日杠杆     (2–3)   — 自动驾驶式的关键行动
```

这防止了"愿景板瘫痪"（100 张随机卡片）并使优先级一目了然。

### 4. **闭合反馈循环**

控制论要求*感知 → 比较 → 调整*。每个时间层级都有反思节奏：

- **每日**：签到 + 意图 + 心情 + 感恩（+ 可选的模式打断）
- **每周**：5 个问题的反思（身份进度 / 反愿景滑坡 / 未来动量 / 项目状态 / 下周杠杆）
- **每月**：隐含的回顾，当新的一月项目被设定时
- **每年**：完整的重启协议（晨间 → 全天 → 夜间合成）

缺少任何一个都会破坏循环。

### 5. **具身化，不是模板**

静态肯定语（"你很有价值"）不起作用，因为它不是*你的*。所有用户界面文本都是从用户自己的地基 + 重启答案生成的：

- "我是那种 [你的身份陈述] 的人"
- "今天我拒绝让我的人生变成 [你的反愿景]"
- "这个月我在打造 [你的月项目]"
- "到 [日期] 有一件事是真的：[你的年镜头]"

即使是 AI 特性（追问 / 镜像 / 连接）也只*提问*——它们永远不写用户的答案。

### 6. **不把核心思考外包给 AI**

按原框架的说法：*"不要试图把这种思考外包给 AI。"*

- 重启协议**禁止 AI 自动填充**；所有 30 个问题都要求手打回答
- AI 只受邀请：提出更聪明的后续问题、镜像矛盾、连接今年与去年的答案
- 产品*设计*防止用户点击"AI 给我写答案"——那个按钮根本不存在

## 产品架构

### A 阶段：身份地基（MVP——第 1–8 周）

#### A1. 身份地基模块（`/foundation`）

一个 5 分钟、一次性 + 可重访的"操作系统配置"，包含 6 个要素：

| 要素 | 提示 | 承诺 |
|------|------|------|
| **反愿景** | "我绝不让我的人生变成……" | 1–2 句生动的恐惧 |
| **愿景** | "我正在打造……" | 1 句话（会演化） |
| **身份陈述** | "我是那种……的人" | 1 句话，深信不疑 |
| **年镜头** | "一年后，这件事是真的……" | 1 个具体、可观测的东西 |
| **月项目** | "这个月我在交付 / 学习……" | 30 天的 boss 战 |
| **约束** | "为了实现愿景，我也不愿放弃……" | 3–5 条游戏规则 |

**数据模型**：版本化（`foundationHistory[]`）；允许用户看到自己的年度演化。

#### A2. 镜头层级（重构愿景板）

从平铺卡片堆 → 4 层任务金字塔重新架构：

- **年镜头**（1 张）— 来自地基
- **月项目**（1–2 张）— 当前季度的目标
- **周任务**（2–4 张）— 每周的小目标
- **日杠杆**（2–3 张）— 自动驾驶行动

每张卡包含：
- 原有字段（图片、进度、子步骤、感受、可视化）
- **新增**：`identityLink` — 这张卡如何服务于你的身份陈述的一句话

**UI**：层级标签页 + 配额指示（免费版：1Y + 1M + 3W + ∞D）

#### A3. 身份驱动的 Dashboard

顶部英雄区：**你当前的身份陈述**（不是静态 i18n 肯定语）。

肯定语旋转木马：从地基自动生成的循环：
- "我是那种……的人"
- "今天我拒绝……"
- "我正在打造……"
- "这个月……"
- "到 [日期]……"

意图输入框提示：*"[身份陈述]版本的你今天会做什么？"*

---

### B 阶段：闭环与协议（第 9–14 周）

#### B1. 重启协议（`/reset`）

旗舰特性：多步向导引导用户完成 1 日框架。

**第 1 部分 / 晨间（15–30 分钟）**：14 个挖掘问题（手写，无 AI，原始答案保留）

**第 2 部分 / 全天**：浏览器推送通知（可配置时间：11am、1:30pm、3:15pm、5pm、7:30pm、9pm）+ 6 + 3 个补充问题；用户记录对每个的简短回答。

**第 3 部分 / 夜间**：8 个合成问题，把用户的原始答案直接漏斗到地基字段（反愿景句子 / 愿景句子 / 身份陈述 / 年镜头 / 月项目 / 日杠杆 / 约束）。

**变体**：
- **完整重启**：每年，完成全部 3 部分（~1 天总时长）
- **迷你重启**：每季度，第 1 + 3 部分蒸馏版（7 个问题，~30 分钟）

**数据模型**：`resetSessions/{sessionId}` 集合；所有提示 + 回答 + 完成时间的不可变记录。启用"时间胶囊"——比较你去年同期的答案。

#### B2. 模式打断（`/interrupt`）

每日推送通知（或如果浏览器通知被拒就用应用内收件箱）在计划的时间显示一个问题 + 60 秒回答框。

问题来自原框架的 9 个日间打断：
- *"我此刻在回避什么？"*
- *"如果有人录下我过去 2 小时的行为，他们会得出我实际上想要什么？"*
- *"我在朝我想要的生活还是我讨厌的生活移动？"*
- （…还有 6 个）

**回答保存到**：`interruptResponses/{userId}/{date}/{time}` — 夜间合成时用来浮现盲点。

**降级**：如果用户拒绝通知权限，应用内收件箱横幅出现（"你有 1 个未回答的打断问题"）。

#### B3. 周复盘（`/reflect/weekly`）

每个周日（用户可配）：5 个问题的反思提示：

1. *"这一周我朝身份陈述移动了多少？"*（1–5 分）
2. *"哪些反愿景行为复发了？"*
3. *"什么感觉最像未来的我？"*
4. *"月项目：超前 / 在轨 / 落后 / 需调整？"*
5. *"下周我承诺的两个日杠杆？"*

完成后生成可分享的"周快照卡" + 反馈进反馈循环（感知 → 比较 → 调整）。

**数据模型**：`weeklyReflections/{uid}_{ISOWeek}`；启用趋势分析（D7/D30/D365 模式）。

---

### C 阶段：智能与社区（持续进行）

#### C1. AI 辅助（思考，不是代做）

AI 特性**严格只读、生成问题**：

- **追问**：用户写完答案后，AI 提一个苏格拉底式的后续，暴露矛盾
  - 例如：用户写"我想要 XYZ，但本周我的行动追求的是 ABC" → AI 镜像这个矛盾
- **镜像**：把 10 周的答案综合成一个第三人称的"你的行为实际上揭示你想要什么"的画像
- **连接**：把今年的重启答案与去年的对比；突出什么演化了 vs. 什么保持不变

所有 AI 使用 Claude API、低温度；**零生成用户答案**。

#### C2. 可选的真理者角色

高级用户可启用"说实话模式"：当用户声称日杠杆但 7 天没完成时，应用浮现一个略带尖锐的提示：

> *"你说你会 [日杠杆] 已经 9 天了，但你没做。你的行为说你实际上想要的是 [相反的东西]。准备好诚实一次吗？"*

语言借自原框架——设计用来绕过理性化。

#### C3. 意识阶段自评（可选）

一次性 + 每季度的 9 阶段自评（从框架 §IV：冲动 → 一体）。

根据阶段调整 UI 语言风格（早期阶段用具体行动语言；后期阶段用抽象意识语言）。

**实验性功能** — 低可见性，不在主导航。

#### C4. 公开身份卡（社区种子）

用户可生成可分享的卡片（Twitter / 小红书 / Threads），包含：
- 他们当前的身份陈述
- 他们当前的年镜头
- 可选：他们的一个日杠杆

匿名化、去标识——但创造了**公开承诺**信号 + 增长的社会证明。

## 实现概览

### 技术栈

- **前端**：React 18 + Zustand（状态） + Tailwind + Vite
- **后端**：Vercel Serverless（Node.js），用于结账 + webhook API
- **数据库**：Firebase Firestore + Auth
- **支付**：Lemonsqueezy（仅年付 $99.99 / 年）
- **AI**：Claude API（可选，仅限付费用户）

### 关键集合（Firestore）

```
users/{uid}
  ├─ subscription* (status, expiresAt, 等)
  ├─ foundation (反愿景, 愿景, 身份, 年镜头, 月项目, 约束)
  └─ lemonsqueezy* (customerId, subscriptionId, 等)

foundationHistory/{uid}_{date}
  └─ 该时刻地基的快照（不可变，用于历史）

resetSessions/{sessionId}
  ├─ 所有 30 个问题 + 用户答案
  ├─ completedAt 时间戳
  └─ kind ('mini' | 'full')

interruptResponses/{uid}/{date}/{time}
  └─ 用户对那天打断的 60 秒回答

weeklyReflections/{uid}_{ISOWeek}
  ├─ 5 个反思答案
  ├─ completedAt
  └─ 反思时刻的地基快照

visionBoard/{docId}
  ├─ 标题、内容、图片、进度、步骤
  ├─ level ('year' | 'month' | 'week' | 'day')  [新增]
  ├─ identityLink（可选，1 句话）[新增]
  └─ （既有字段：分类、优先级、截止日期等）
```

### Firestore 安全规则

- 所有集合按所有者范围（`userId` 字段检查）
- `subscriptionStatus` / 计费字段受保护：只有 Admin SDK 可写（仅 Lemonsqueezy webhook）
- 地基版本化：旧版本不可变
- 重启会话：创建后不可变

### API 端点（Vercel Serverless）

```
POST /api/create-checkout
  ├─ 认证：Firebase ID token
  └─ 返回：Lemonsqueezy 购物车 URL

POST /api/lemonsqueezy-webhook
  ├─ 认证：HMAC-SHA256 签名验证
  ├─ 摄取：订阅生命周期事件
  └─ 更新：users/{uid} 计费字段
```

### i18n 与本地化

- **A 阶段**：EN + 中文完全翻译
- **B+ 阶段**：EN + 中文；其他 7 种遗留语言回到旧界面
- 重启 / 地基提示保留为结构化 i18n 键（vs. 嵌入式文本）
- 社区翻译在上线后接受

### 前端到后端数据流

```
用户填写地基
  ↓（模糊保存，防抖）
Cloud Function 写入 foundation/{uid}
  ↓
Zustand 存储通过 onSnapshot 监听（实时）
  ↓
Dashboard / 所有下游特性响应式重新渲染身份陈述
```

无轮询；所有更新在 1–2 秒内触发。

## 商业化模式

### 哲学：单档年度承诺

**为什么不是多档位？**
- 减少决策瘫痪（免费用户不会中途想知道自己在"错过"什么）
- 年付创造心理上的"身份锁定"（支付 $99.99 = "我今年对身份工作是认真的"）
- Lemonsqueezy 的年度流失率自然低于月度（12 个月日历锚点 = 周年续费提醒）
- 运营简化：一个付费墙、一个特性门、一个支持故事

### 免费版

- 1 个活跃地基版本（覆盖前一个，无历史）
- Dashboard 身份陈述 + 肯定语循环
- 愿景板**有限**：1Y + 1M + 3W + ∞D 张卡
- 日签到 / 心情 / 意图 / 感恩：无限制
- **迷你重启**：每季度 1 次
- **周复盘**：最近 4 周可见；更旧的隐藏

### 年度版（$99.99/年）

- ✅ 地基**无限版本** + 演化时间线
- ✅ 愿景板**无限**卡片（全部层级）
- ✅ **完整重启协议**（每年 1–2 次推荐）
- ✅ 模式打断：完整 6 时段 + 自定义时间 + 历史
- ✅ 周复盘：**全部历史** + 年同期对比
- ✅ AI 追问 / 镜像 / 连接（限 200 次调用 / 月）
- ✅ 公开身份卡分享（去标识化）
- ✅ 年末复习 PDF（自动生成，可分享）

### Lemonsqueezy 集成

**最少配置**：1 个产品、年度复现、自动续费。

**Webhook 流程**：
1. 用户点击升级 → 调用 `/api/create-checkout`（用 ID token 认证）
2. API 创建 Lemonsqueezy 结账，带 `meta.custom_data.uid = user.uid`
3. 用户支付 $99.99；LS webhook 触发 `subscription_created` 事件
4. Webhook 处理器验证 HMAC 签名 + 更新 `users/{uid}.subscriptionStatus = 'active'`
5. Zustand `useSubscription()` hook 通过 onSnapshot 监听 `user` 文档
6. UI 重新渲染：侧边栏徽章改变、付费特性解锁

**宽限期**：如果支付失败，用户保留访问权限直到 `subscriptionExpiresAt` 日期。温和降级，不是立即锁定。

### 定价理由

- $99.99 = $8.33 / 月，位于月度瑜伽课（$12–15）和年度课程（$500）之间
- 单一触发：*"我今年对身份工作是认真的"* — 匹配年度重启日节奏
- Lemonsqueezy 处理税费 / VAT / 货币 — 无需手动开票

## 成功指标与假设

### 关键假设

1. **免费 → 年度转化**：5% 的免费用户会升级
   - 锚点：完成地基会激发对重启的意识
   - 触发：首次尝试完整重启时显示"升级全部"提示
2. **身份驱动的参与**：完成地基的用户的 D7/D30 留存比跳过的高 2 倍
3. **周复盘闭合循环**：每月完成 4+ 次周复盘的用户显示比对照组高 40% 的目标完成率
4. **反愿景驱动力比愿景更强**：有生动反愿景文本的重启会话比仅有正面愿景的后续跟进率高

### 仪器

- **Amplitude**：跟踪地基完成率、重启尝试率、周复盘完成率、特性解锁事件
- **Firestore**：查询 `resetSessions`、`foundationHistory`、`weeklyReflections` 计算群组统计
- **Lemonsqueezy**：监察年度续费率、流失率、支付衰退趋势
- **定性**：每月给 10% 的年度版用户发邮件，开放式提示"到目前为止你的身份转变是什么？"
